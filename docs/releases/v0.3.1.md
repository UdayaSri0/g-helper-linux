# rog-helper v0.3.1

This stability and hardware-control hardening release follows
[`v0.3.0...v0.3.1`](https://github.com/UdayaSri0/g-helper-linux/compare/v0.3.0...v0.3.1).

## Lighting and privileged control

- Adds capability-driven lighting controls with validated colours, effect options, pending state,
  reset, and dirty-only Apply behavior.
- Hardens the ASUS Aura backend: the native route is limited to the exact G615JMR identity
  (`0b05:19b6`, interface `00`, DMI prefix `G615JM`) and validates its HID descriptor and protocol
  before use.
- Adds the typed privileged API v2 `SetAuraEffect` operation and a root-only Aura udev alias. The
  helper accepts neither caller-selected paths nor raw HID report bytes.
- Extends `rog-helper privileged-status` with helper/API compatibility, D-Bus, PolicyKit, udev,
  and Aura readiness diagnostics.

## Reliability and packaging

- Preserves pending control edits across daemon polling instead of replacing a user selection with
  stale reported state before Apply.
- Strengthens Debian package installation, upgrade, removal, payload validation, session D-Bus
  activation, and user-service lifecycle checks.
- Adds package lifecycle gates to CI and the release workflow before native release publication.

## Release assets

The release workflow publishes native packages and direct binaries, including:

- `rog-helper_0.3.1_amd64.deb`
- `rog-helper-0.3.1-1.x86_64.rpm`
- `rog-helper-v0.3.1-x86_64.AppImage`
- `rog-helper-0.3.1-linux-x86_64.tar.xz`
- `rog-helper`, `rog-helperd`, and `rog-helper-ui`
- SHA-256 manifests for the native package groups

## Known limitations

- Native Aura support is limited to the exact allow-listed G615JMR target and RGB effects only;
  ARGB, zones, and per-key control are not supported.
- Native Aura has no reliable effect-state readback. `accepted_no_readback` is not proof that the
  keyboard physically changed, and physical Aura validation is still outstanding.
- The asusd Aura route is limited to the verified 6.3.8–6.4.0 D-Bus contract. Unknown devices and
  contracts remain diagnostic-only.
- `asusd` and `supergfxd` are optional; available controls depend on the host hardware and service
  state. Privileged operations require applicable PolicyKit authorization.
- AppImage cannot safely install the privileged helper, system D-Bus policy, PolicyKit policy,
  systemd units, or udev rule. Use a native package for that integration.
