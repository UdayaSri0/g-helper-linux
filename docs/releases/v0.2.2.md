# rog-helper v0.2.2

This release prepares the next packaging-enabled release of rog-helper and keeps the Rust workspace, package metadata, documentation, and GitHub release automation aligned on `v0.2.2`.

## Highlights

- Updated the project version from `0.2.1` to `0.2.2`.
- Refreshed release-facing documentation and metadata for the new release.
- Verified that the release workflow is aligned with the Git tag `v0.2.2`.
- Preserved the existing packaging targets for Debian/Ubuntu/Linux Mint, Fedora-style RPM systems, portable AppImage usage, tarball installs, and direct binary downloads.
- Improved tray/window lifecycle UX while keeping an explicit full-exit path.
- Kept known limitations documented clearly instead of overstating hardware support.

## What Changed Since v0.2.1

- Window close behavior now defaults to hiding the main window to the tray when tray support is available.
- Tray Quit and the About-page lifecycle Quit action remain explicit full-exit paths.
- Added limited UI lifecycle preferences for close behavior, launch on login, and start minimized to tray.
- Added `--minimized-to-tray` startup support for quiet background startup.
- Added a compact live tray status summary with power source, battery percentage, CPU temperature, GPU temperature, profile, and GPU mode when available.
- Improved tray fallback behavior so the app keeps the main window open when StatusNotifierItem support is unavailable.
- Refined diagnostics page scrolling and text wrapping behavior.
- Added GTK resource/icon polish for the UI navigation icons.
- Kept the GitHub repository URL, issue URL, desktop metadata, AppStream metadata, and package metadata aligned with `https://github.com/UdayaSri0/g-helper-linux`.
- Fixed the Clippy `question_mark` lint in GitHub repository URL parsing so release CI can run with `-D warnings`.
- Tightened release checksum generation so the main SHA256 file tracks the published non-RPM Linux assets instead of diagnostic logs.
- Updated release/install examples and Arch packaging metadata for `0.2.2`.

## Installation Options

### Debian, Ubuntu, Linux Mint

```bash
sudo dpkg -i rog-helper_0.2.2_amd64.deb
sudo apt-get install -f
```

Or install directly with apt:

```bash
sudo apt install ./rog-helper_0.2.2_amd64.deb
```

Optional user-session daemon enablement:

```bash
systemctl --user daemon-reload
systemctl --user enable --now rog-helperd.service
```

### Fedora-style RPM systems

```bash
sudo dnf install ./rog-helper-0.2.2-1.x86_64.rpm
```

Optional user-session daemon enablement:

```bash
systemctl --user daemon-reload
systemctl --user enable --now rog-helperd.service
```

### AppImage

```bash
chmod +x rog-helper-v0.2.2-x86_64.AppImage
./rog-helper-v0.2.2-x86_64.AppImage
```

The AppImage is portable and does not install a system menu entry or enable the user service on the host.

### Tarball

```bash
sudo tar --strip-components=1 -xf rog-helper-0.2.2-linux-x86_64.tar.xz -C /usr/local
sudo update-desktop-database /usr/local/share/applications || true
sudo gtk-update-icon-cache -q /usr/local/share/icons/hicolor || true
systemctl --user daemon-reload
systemctl --user enable --now rog-helperd.service
```

### Direct binaries

The direct `rog-helper`, `rog-helperd`, and `rog-helper-ui` binaries are intended for advanced user-local installs and for the UI's safe direct-binary update path. They do not install desktop metadata or services by themselves.

## Known Limitations

- Fan curve editor and daemon API are not implemented end-to-end.
- Aura/RGB support depends on asusd exposing a compatible Aura/keyboard lighting DBus backend and still needs broader hardware validation.
- Live auto mode / policy automation is not wired into the daemon.
- Persistent hardware/control configuration and saved automation rules are not implemented beyond the limited UI lifecycle preferences.
- DBus payloads are still string-keyed maps rather than typed shared structs.
- AppImage desktop integration is not automatic.
- The project does not ship a privileged helper, bundled polkit rules, bundled udev rules, or a root daemon.

## Hardware Support Notes

- No new committed hardware validation records were added for this release.
- The code is capability-aware and should degrade when services, permissions, or sysfs endpoints are missing, but that is not the same as broad hardware certification.
- Treat ASUS model support, distro behavior, desktop tray behavior, and write-permission behavior as untested unless a real validation record exists in the repository.
- `asusd` is required for ASUS performance profile and battery charge-limit control.
- `supergfxd` is required for GPU mode control.
- Writable sysfs permissions are required for CPU writes and keyboard backlight writes.
