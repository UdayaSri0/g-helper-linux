# ROG Helper v0.4.1 — Stability, Security and Compatibility Update

**Draft for release review — not published.** These notes describe the prepared candidate, not a released binary. The actual release date and final asset inventory are pending approval and candidate CI.

## Release summary

This stability candidate focuses on safer Debian package dependencies, actionable checksum verification, fail-closed hardware controls, and packaging/reliability checks accumulated since v0.4.0. Hardware support remains backend- and model-dependent.

## Main fixes

- The DEB dependency candidate uses `polkitd`, the system PolicyKit authority package, and rejects the obsolete `policykit-1` dependency.
- Release install instructions download the artifact and its separate checksum manifest, then verify the exact selected file.
- Unsigned in-place executable replacement remains disabled. Update checks direct users to the manual Releases page until an authenticated artifact trust design is ready.
- Fan writes are restricted by verified capability and safety policy; missing telemetry and helper interruption have fail-closed/recovery coverage.
- Battery-source freshness, restart/resume handling, and reversible policy logic received software safeguards. Automatic battery hardware writes remain disabled.
- Package lifecycle and session tests use isolated fixtures/mocks; they do not substitute for native distro installation or physical hardware validation.

## Debian/Ubuntu installation compatibility

The candidate DEB declares `polkitd`; on the Ubuntu 26.10 test host, APT metadata had a `polkitd` candidate and no `policykit-1` candidate. APT dependency resolution was simulated successfully against the locally built package. **A native install was not performed**, so installed service, CLI, GUI, D-Bus, and PolicyKit behavior remain unverified.

The local DEB also declares `libc6 (>= 2.39)`. The oldest compatible Debian-family release has not been established; the supported distribution floor must be confirmed before this draft is used as public compatibility guidance.

The published v0.4.0 install examples in the [README](../../README.md) continue to reference v0.4.0 assets. Do not substitute v0.4.1 download URLs until an approved release exists and its asset names are confirmed.

## Checksum verification

The DEB instructions were run from a fresh directory against the actual v0.4.0 release asset and reported:

```text
rog-helper_0.4.0_amd64.deb: OK
```

The RPM, AppImage, and tarball examples were checked against the published asset list but were not independently downloaded and verified. A checksum file downloaded from the same release location detects mismatches; it does not independently authenticate the publisher.

## Updater security behavior

Automatic executable replacement remains disabled. The UI uses a manual GitHub Releases path pending a signed manifest and pinned key. Do not treat checksums hosted beside a binary as publisher authentication.

## Hardware safety

Fan curve Apply/Auto/recovery and native Aura physical effects have not been physically validated. Related controls remain gated for unverified hardware. A successful D-Bus response is not evidence of physical behavior. Battery automatic hardware writes remain disabled.

## Battery automation status

Source freshness, hysteresis/reversibility, and suspend/resume software protections are present in the current main history. PR #118 adds a stricter post-event refresh barrier and has passing listed CI checks, but it remains open for separate human review. Do not merge or enable it as part of this release without that review and physical evidence.

## Packaging and test improvements

The candidate local build produced a DEB, tarball, direct CLI/UI/daemon/privileged binaries, and a SHA256 manifest. The DEB payload/lifecycle checks and all six staged checksum entries passed. RPM and AppImage were not built locally. Candidate CI has not run.

## Installation, upgrade, and supported distributions

The v0.4.1 install and upgrade commands must be generated from the final release asset list after approval. Ubuntu 26.10 dependency resolution was simulated; native installation was not tested. Ubuntu 24.04/26.04, Linux Mint, Debian, Fedora/RPM, and AppImage runtime compatibility are UNTESTED for this candidate.

See [BUILD.md](../BUILD.md) for existing v0.4.0 examples and packaging development guidance. Do not use draft candidate artifacts as production packages.

## Known limitations and security considerations

- No physical fan, Aura, or other hardware behavior is claimed as verified.
- The generated DEB's libc and other shared-library floors have not been checked on the oldest claimed distribution.
- AppImage cannot install system-level privileged integration; RPM/AppImage candidate validation remains pending.
- The updater remains manual-only; authenticated in-place updates are deferred.
- Same-origin SHA256 manifests provide mismatch detection, not independent authenticity.
- RustSec reports unmaintained warnings for `zbus_names`, `zvariant`, and `zvariant_derive`; no lockfile vulnerability finding was reported.

## Full changelog since v0.4.0

- **Hardware safety:** stricter fan write gates, transaction/recovery handling, safe behavior when owned sensor data disappears, and corresponding fixture coverage (#86, #87, #109, #110).
- **System reliability:** bounded display/NVIDIA subprocess handling, safer CPU rollback, GPU readiness gates, and daemon operation when system D-Bus is unavailable (#96, #99, #100, #103).
- **Updater/security:** invalidate stale update actions and disable unsigned executable replacement; add an updater trust proposal (#105, #114). Authenticated replacement remains deferred.
- **Dependency and API review:** RustSec remediation and audit policy coverage; versioned UI/daemon D-Bus contract (#106, #107).
- **Packaging/QA:** GTK/AppImage build-tool integrity and compatibility checks; isolated RPM/DEB lifecycle tests; packaged AppImage/session smoke coverage (#111–#115).
- **Battery policy:** stale source samples fail closed; reversible opt-in profile policy was added, with physical transition/resume validation still outstanding (#116, #117).
- **Release fixes in this candidate:** replace the obsolete DEB PolicyKit dependency (#119) and make checksum instructions self-contained (#120).
- **Release preparation:** v0.4.1 package/version metadata is staged; the AppStream release date and final binary inventory await publication approval.

## Comparison with v0.4.0

v0.4.0 introduced named presets, opt-in AC/Battery automation, graphical eight-point fan curves, X11 refresh-rate controls, and additional diagnostics. v0.4.1 is a stability candidate that adds the DEB/checksum fixes above and carries forward later safety and packaging hardening. It adds no new hardware capability claim.
