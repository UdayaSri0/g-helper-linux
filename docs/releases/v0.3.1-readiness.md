# v0.3.1 Release Readiness

This is the evidence record for the `v0.3.1` release candidate. It does not inherit validation
claims from the historical `v0.3.0` record.

## Metadata and scope

- Workspace package version: `0.3.1`.
- Required immutable tag: `v0.3.1`.
- Previous release: `v0.3.0`.
- Candidate scope: lighting/Aura hardening, typed privileged API v2 diagnostics, package lifecycle
  reliability, and polling draft preservation. No broad hardware allow-list or raw-HID interface is
  added.

## Required final-candidate gates

| Gate | Evidence required before tagging |
| --- | --- |
| Source quality | `cargo fmt --all -- --check`, locked workspace build/test, and Clippy with warnings denied |
| Metadata | `python3 packaging/scripts/check-release-metadata.py` and clean version/reference review |
| Debian lifecycle | mocked installer and maintainer checks, freshly built `.deb`, payload inspection, and isolated upgrade/remove lifecycle test |
| Release workflow | tag/version check and package lifecycle gates in `.github/workflows/release.yml` |
| Security | typed/path-free/raw-byte-free helper boundary, narrow PolicyKit actions, root-only Aura alias, and exact native identity/protocol checks |
| Publication | final main CI, immutable tag on the merged main SHA, release workflow, downloaded assets, and verified SHA-256 manifests |

## Hardware evidence and limitations

Automated checks cover input validation and API contracts. No physical G615JMR Aura Apply result is
recorded; accepted writes without readback are not physical verification. No untested hardware,
distro, PolicyKit-agent, or tray scenario is represented as passed. See
[HARDWARE_SUPPORT.md](../HARDWARE_SUPPORT.md) for the complete untested matrix.
