## Rust dependency audit

Repository audit policy check passed using cargo-audit 0.22.2 and advisory database revision `7f6085443f236889cc5df7e54078b0a0193bd95a`. No candidate lockfile vulnerabilities were reported. Three unmaintained warnings remain:

| Advisory | Crate | Locked version | Status |
|---|---|---:|---|
| RUSTSEC-2026-0371 | `zbus_names` | 4.3.1 | Unmaintained warning |
| RUSTSEC-2026-0370 | `zvariant` | 5.9.2 | Unmaintained warning |
| RUSTSEC-2026-0372 | `zvariant_derive` | 5.9.2 | Unmaintained warning |

These are unmaintained warnings, not known vulnerabilities. A direct zbus 6 upgrade is not a safe v0.4.1-only bump: it is a major API/MSRV migration, while the current KSNI tray dependency remains on zbus 5. Keep current versions and warnings visible for this release; plan a coordinated zbus 6 migration when KSNI supports it or the tray dependency changes, then rerun the full workspace tests, RustSec audit, and distro build/runtime checks. Do not suppress the warnings.

## Privilege boundaries

- The app does not invoke `pkexec`; it requests authorization through the system PolicyKit authority over D-Bus.
- #119 changes only the DEB runtime dependency from `policykit-1` to `polkitd`, updates final-metadata validation, and adds regression coverage.
- The privileged helper remains typed and restricted; no arbitrary filesystem paths, raw HID commands, broad permissions, or root UI/daemon execution were introduced.
- Package payload checks passed for the staged DEB, and installed 26.10 executable hashes match that DEB. Ubuntu 24.04 native install/service checks and safe denial passed in CI. The installed 26.10 PolicyKit backend reports available, but interactive prompts and authorization outcomes remain untested.

## Checksum trust

The v0.4.0 exact-file flow was downloaded into an empty directory and verified. SHA256 comparison against a manifest fetched from the same GitHub release origin detects corruption/mismatch but does not independently authenticate the publisher. No signed v0.4.1 artifacts exist.

## Remaining security gates

- Record Ubuntu 26.10 upgrade/removal/purge evidence; fresh install is recorded, while later lifecycle steps are not.
- Test PolicyKit denial/cancellation in the target agent without approving a hardware action.
- Keep automatic executable replacement disabled until signed/pinned trust is independently reviewed.
- Track the three unmaintained warnings with the coordinated KSNI/zbus migration plan.
- Maintain fail-closed hardware gates; physical fan/Aura behavior remains unverified.
