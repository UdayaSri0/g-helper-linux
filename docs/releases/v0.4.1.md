# ROG Helper 0.4.1

ROG Helper 0.4.1 is a stability update focused on packaging correctness, safer
failure handling, and clearer release verification. Hardware support remains
dependent on the laptop model and available Linux providers.

## Highlights

- Debian packages now depend on the system PolicyKit authority package,
  `polkitd`.
- Release download instructions explain how to verify the checksum for the
  exact package selected.
- Diagnostics and service integration better report missing providers,
  compatibility, and hardware capabilities.
- Package and session checks cover installation lifecycle, service activation,
  and missing-provider behavior using isolated test environments.
- Hardware write paths remain capability-gated. Unverified fan and Aura
  behavior is not claimed as supported or physically validated.

## Security and hardware safety

Unsigned in-place executable replacement remains disabled. Update checks direct
users to manual downloads until signed release metadata and a pinned key are
available.

Custom fan control remains fail-closed unless the exact hardware capability and
safety requirements have been verified. Generic PWM and other uncertain
controls remain read-only. Automatic battery hardware writes remain disabled.
No new physical fan, Aura, battery, CPU, or GPU behavior is claimed by this
release.

### Security limitations

RustSec reports four unmaintained dependencies in the locked dependency graph:
`zbus_names 4.3.1` (RUSTSEC-2026-0371), `zvariant 5.9.2`
(RUSTSEC-2026-0370), `zvariant_derive 5.9.2` (RUSTSEC-2026-0372), and
`pin-utils 0.1.0` (RUSTSEC-2026-0441). These are maintenance notices, not
confirmed exploitable vulnerabilities; the current audit found no lockfile
vulnerability advisory. SHA-256 manifests are served with the release assets
and detect mismatches, but are not independently authenticated signatures.

## Compatibility and validation

Ubuntu 24.04 package acceptance covered installation, upgrade from 0.4.0,
removal and purge, service and D-Bus integration, CLI diagnostics, headless GTK
startup, missing-provider behavior, and a safe PolicyKit denial.

On Ubuntu 26.10, a fresh installation from the local 0.4.1 DEB and read-only
runtime diagnostics were observed. An upgrade from 0.4.0, removal and purge,
interactive GUI behavior, and interactive PolicyKit prompts were not verified
there. Ubuntu 26.04 and Debian 13 have dependency-resolution evidence only. The
tested DEB is incompatible with Debian 12. These results do not establish a
general supported-distribution floor.

## Download and verification

In an empty directory, download the intended DEB and its matching manifest,
extract exactly one checksum entry for that filename, and verify it before
installation:

```sh
set -eu
curl -fLO https://github.com/UdayaSri0/g-helper-linux/releases/download/v0.4.1/rog-helper_0.4.1_amd64.deb
curl -fLO https://github.com/UdayaSri0/g-helper-linux/releases/download/v0.4.1/rog-helper-0.4.1-SHA256SUMS.txt
asset=rog-helper_0.4.1_amd64.deb
manifest=rog-helper-0.4.1-SHA256SUMS.txt
test -s "$asset" && test -s "$manifest"
grep -E '^[[:xdigit:]]{64}  rog-helper_0\.4\.1_amd64\.deb$' "$manifest" > "$asset.sha256"
test "$(wc -l < "$asset.sha256")" -eq 1 || { echo "Expected exactly one checksum entry" >&2; exit 1; }
sha256sum --check "$asset.sha256" || { echo "Checksum verification failed; do not install" >&2; exit 1; }
sudo apt install "./$asset"
```

The exact-name expression rejects other assets and `wc -l` rejects duplicate
entries. Stop if either download, entry check, or checksum verification fails.
Because the manifest is hosted with the release assets, it detects corruption
but is not equivalent to an independently authenticated digital signature.
