# rog-helper v0.2.0

This is the first `rog-helper` release built around installable Linux packages
instead of a source-only tag.

## Highlights

- tagged releases now publish installable Linux artifacts instead of only source snapshots
- workspace, crates, desktop metadata, icons, and About-page metadata are aligned on `v0.2.0`
- desktop integration assets are now shipped consistently across native packages and portable bundles
- release automation now builds checksummed package artifacts on tag push

## Published Release Assets

- GitHub still provides the standard source tarball and source zip for the `v0.2.0` tag
- `rog-helper_0.2.0_amd64.deb` for Debian, Ubuntu, and Linux Mint-style installs
- `rog-helper-0.2.0-1.x86_64.rpm` for Fedora Workstation-style installs
- `rog-helper-v0.2.0-x86_64.AppImage` for portable download-and-run usage
- `rog-helper-0.2.0-linux-x86_64.tar.xz` for prefix-friendly `/usr/local` installs
- direct `rog-helper`, `rog-helperd`, and `rog-helper-ui` binaries for advanced local installs
- `rog-helper-0.2.0-SHA256SUMS.txt` and `rog-helper-0.2.0-RPM-SHA256SUMS.txt`

## Native Install Options

- Debian-family users can install the `.deb` and get `/usr/bin` binaries, desktop launcher integration, AppStream metadata, icons, session D-Bus activation, and the `systemd --user` unit
- Fedora-family users can install the `.rpm` with the same core binaries and desktop integration layout under standard Fedora paths
- portable users can run the AppImage directly or unpack the Linux tarball into `/usr/local`

## In-Repo Packaging Support

- the repository now includes a source-based Arch `PKGBUILD`, `.SRCINFO`, and install hook for Arch and future AUR publishing work
- the repository now includes a Flatpak manifest, vendored Cargo dependency manifest, and local build helper
- these Arch and Flatpak files are packaging metadata in the repository; they are not published release artifacts from the GitHub release workflow today

## Desktop Integration

- `rog-helper-ui`, `rog-helperd`, and `rog-helper` now ship with aligned desktop entry, icon name, AppStream metadata, and repository metadata
- generated hicolor icon assets are included in native packages and portable bundles
- session D-Bus activation and packaged daemon paths are wired for non-source installs

## Known Limitations

- hardware support is still evidence-based and remains limited to tested machines documented in the repository
- the AppImage does not auto-install desktop integration or enable a persistent host `systemd --user` service
- Flatpak support is included in-repo, but sandboxing limits direct sysfs writes, narrows procfs visibility, and still depends on host services such as `asusd`, `supergfxd`, and `UPower`
- the Arch packaging is AUR-ready, but no AUR repository is published automatically from this release
- a future APT repository preview can be staged from the repository, but no signed public APT repository is live yet
