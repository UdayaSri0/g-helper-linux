# rog-helper v0.3.0

rog-helper v0.3.0 is a major early-development milestone for the Linux-native ASUS ROG control application. It delivers the redesigned Dashboard 3.0 experience, substantially broader diagnostics and telemetry, safer capability-aware controls, an optional PolicyKit-gated privileged helper, and a more complete multi-format Linux packaging pipeline.

## Highlights

- Introduced Dashboard 3.0: a responsive GTK4/libadwaita cockpit with live CPU, GPU, memory, storage, battery, power, cooling, and system-health views.
- Expanded CPU telemetry and control with physical-core and logical-thread visibility, per-thread state, frequency limits, governors, energy preferences, boost, and structured access diagnostics.
- Added dynamic fan discovery, polished RPM monitoring, animated fan rotors, CPU/GPU gauges, and verified ASUS WMI eight-point fan-curve support.
- Added Setup & Access checks that explain service, backend, capability, and permission problems without using sudo or changing the system.
- Added an optional, typed, PolicyKit-gated privileged service for narrowly scoped CPU, battery, fan, and lighting writes.
- Strengthened packaging for Debian/Ubuntu/Linux Mint, Fedora-family RPM systems, AppImage, prefix tarballs, Arch metadata, Flatpak validation, and direct binaries.
- Improved lifecycle behaviour with tray status, close-to-tray, launch-on-login, and start-minimised preferences.
- Added manual update checks, release-note previews, source/support links, and issue-reporting actions to the About page.

## Dashboard and User Interface

- Rebuilt the main window around a responsive navigation shell and reusable card/widget system.
- Added At a Glance, System Overview, Quick Performance, Cooling Snapshot, Live Performance, and System Health sections.
- Added 60-second performance sparklines and calm unavailable/read-only states instead of misleading controls.
- Improved the Fans page with individual fan cards, dynamic 0..N fan inventory, RPM animation, operating MHz display, curve preview, and copyable diagnostics.
- Improved navigation icons, application branding, desktop metadata, tray/window icon naming, and embedded GTK resources.
- Kept CPU on the left and GPU on the right in the cooling presentation.

## Hardware, Telemetry, and Controls

- Added richer CPU topology, temperature, utilisation, clock, policy, online/offline, and write-capability reporting.
- Improved GPU telemetry with `supergfxd` integration and a read-only `nvidia-smi` fallback where available.
- Expanded battery, power, memory, pressure-stall, zram/zswap, storage, keyboard-backlight, and ASUS profile reporting.
- Added verified eight-point ASUS WMI fan-curve writes with identity/channel checks and Auto/BIOS restoration.
- Added keyboard brightness and battery-threshold privileged fallbacks while preserving direct or service-native routes as the first choice.
- Added hardware-report, setup-check, fan diagnostics, capability inspection, and lighting diagnostics to the CLI.

## Safety and Security

- The GTK UI and session daemon remain unprivileged.
- The optional root helper exposes typed, path-free methods; callers cannot provide arbitrary paths, commands, executables, or raw hardware payloads.
- Separate PolicyKit actions protect CPU, battery, fan, and lighting operations.
- The privileged service uses systemd hardening and rejects malformed, out-of-range, unsupported, or disappearing endpoints.
- Generic PWM, arbitrary RPM-target, boost, and unverified Aura/RGB writes remain disabled.
- Manual fan curves are validated, dangerous curves are rejected, and supported operations restore Auto/BIOS mode after interruption or timeout.
- Setup diagnostics remain read-only and never install packages, invoke sudo, modify permissions, or bypass DBus policy.

## Installation

### Debian, Ubuntu, and Linux Mint

```bash
sha256sum -c rog-helper-0.3.0-SHA256SUMS.txt --ignore-missing
sudo apt install ./rog-helper_0.3.0_amd64.deb
systemctl --user daemon-reload
systemctl --user enable --now rog-helperd.service
```

### Fedora-family systems

```bash
sha256sum -c rog-helper-0.3.0-RPM-SHA256SUMS.txt --ignore-missing
sudo dnf install ./rog-helper-0.3.0-1.x86_64.rpm
systemctl --user daemon-reload
systemctl --user enable --now rog-helperd.service
```

### AppImage

```bash
chmod +x rog-helper-v0.3.0-x86_64.AppImage
./rog-helper-v0.3.0-x86_64.AppImage
```

### Prefix tarball

```bash
sudo tar --strip-components=1 -xf rog-helper-0.3.0-linux-x86_64.tar.xz -C /usr/local
sudo update-desktop-database /usr/local/share/applications || true
sudo gtk-update-icon-cache -q /usr/local/share/icons/hicolor || true
systemctl --user daemon-reload
systemctl --user enable --now rog-helperd.service
```

## Known Limitations

- Broad ASUS model support is not certified; hardware is considered validated only when a reviewed machine record exists.
- Generic manual PWM duty, arbitrary RPM-target, and generic fan boost writes remain unsupported.
- Aura/RGB writes require an exact compatible and verified `asusd` contract and still need broader hardware coverage.
- Live automatic policy integration and persistent hardware/control automation are not implemented end-to-end.
- Some DBus payloads remain backwards-compatible string-keyed `a{sv}` maps.
- AppImage desktop integration and service installation are not automatic.
- Installed launch, upgrade, uninstall, tray, browser/update, and cross-distro behaviour still require broader real-system verification.
- CPU, battery, lighting, GPU-mode, and fan writes depend on detected hardware, backend availability, and authorisation.
- Missing `asusd` or `supergfxd` reduces the corresponding ASUS profile, battery-limit, lighting, or GPU-mode capability.

## Upgrade Notes

- Stop any manually launched development daemon before installing a package.
- Install the new package over the previous version, then reload and restart the user service.
- If the UI reports stale capabilities, restart `rog-helperd.service` and use Setup & Access or `rog-helper setup-check`.
- Review PolicyKit prompts carefully; cancelling or denying authorisation leaves hardware unchanged.
